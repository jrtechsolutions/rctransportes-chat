01 · Visão geral

O que o sistema cobre

Um único ambiente para atendimento via WhatsApp, ocorrências e pendências operacionais, check-in de KM e notas de coleta lidos por foto, chamados de expedição por unidade (com painel de TV), indicadores gerenciais e cadastros de usuários, motoristas e clientes — com permissões por tela.

Atendimento Inbox estilo WhatsApp, SLA, transferência, encerramento com a lista completa de 149 motivos e 19 resultados da RC.
Ocorrências, Pendências & KM Protocolos com prioridade/prazo, pendências com responsável e prazo, KM lido da foto com correção manual.
Notas de coleta Motorista, agregado ou ajudante envia a foto da DANFE; o sistema lê emitente, CNPJ, número e chave de acesso e confere a chave.
Expedição Chamados para Matriz ou Filial, acompanhamento por quem abriu (com complementos) e Painel TV full-screen.
Gestão Dashboard (~15 KPIs + gráficos, incluindo pendências vencidas) e 10 relatórios com exportação Excel/PDF.
Administração Config. de setor, usuários com unidade de expedição, motoristas/agregados/ajudantes, clientes com chatbot próprio, falhas de integração e auditoria.
Importante: as telas abaixo são o protótipo visual (dados fictícios) para fechar escopo e preço. A seção seguinte descreve as linguagens e tecnologias que serão usadas na implementação real.
Incluído nesta revisão do protótipo
  • Pendências como entidade própria (tela, vínculo com ocorrência/atendimento, indicadores e relatório)
  • Lista completa de motivos e resultados enviada pela RC
  • Notas de coleta: leitura automática da DANFE enviada por foto
  • Correção manual do KM quando a foto do odômetro for lida errado
  • Chamados de expedição divididos em Matriz e Filial, com acompanhamento e complementos de quem abriu
  • Cadastro de clientes (2 WhatsApp + chatbot por cliente) e tipo Ajudante no cadastro de motoristas
  • Unidade de expedição e criação de setor no cadastro de usuário
  • Telas de falhas de integração do WhatsApp e log de auditoria
  • Menu lateral recolhível (só ícones)
02 · Stack técnico

Linguagens e tecnologias do projeto

Stack já definida no repositório (frontend + backend). TypeScript de ponta a ponta — mesma linguagem no browser e no servidor, com tipagem forte e menos atrito entre as equipes.

Frontend Interface web

  • TypeScript — linguagem principal
  • React 18 — componentes e telas
  • Vite — build e servidor de desenvolvimento
  • React Router — rotas e proteção de telas
  • CSS Modules — estilos por tela (identidade RC)
  • Recharts — gráficos do Dashboard
  • Socket.io Client — atualização em tempo real

Backend API e serviços

  • TypeScript (Node.js) — linguagem do servidor
  • Fastify — API HTTP de alta performance
  • Prisma — ORM e migrations
  • Zod — validação de payloads
  • Socket.io — push (conversas, painel TV, chamados)
  • Nodemailer — envio de e-mails (confirmação de chamado)
  • tsx — execução em desenvolvimento

Banco Persistência

  • PostgreSQL — banco relacional principal
  • Prisma Migrate — versionamento do schema
  • Entidades: usuários, setores, atendimentos, mensagens, ocorrências, pendências, KM, notas de coleta, chamados, clientes, motoristas, números WhatsApp
  • Registro de auditoria e de falhas de integração
  • Índices e enums tipados no schema (status, papéis, unidade, direção da mensagem…)

Segurança Auth e proteção

  • Microsoft Entra ID (Azure AD) via MSAL — login corporativo
  • JWT (access + refresh) — sessão da API
  • Cookies HTTP-only — refresh token
  • Rate limit (@fastify/rate-limit) — proteção contra abuso
  • CORS configurado + validação Zod em rotas
  • Permissões por tela + unidade de expedição (Matriz/Filial) por usuário
  • Log de auditoria — quem alterou o quê (atendimentos, ocorrências, pendências, KM, cadastros, setores)
  • Socket autenticado com JWT no handshake

Integrações WhatsApp, IA e tempo real

  • WhatsApp Business API — webhook de entrada + envio de mensagens
  • Número cadastrado (cliente, motorista, agregado ou ajudante) define o chatbot enviado
  • Leitura de imagem com IA — odômetro (KM) e DANFE (emitente, CNPJ, número, chave)
  • Leitura do código de barras da DANFE + conferência da chave (dígito verificador, CNPJ e número)
  • Registro de falhas de integração com reprocessamento
  • Socket.io — fila ao vivo por setor e painel de TV
  • E-mail de confirmação nos chamados de expedição

Ops Ambiente e entrega

  • Monorepo: pastas frontend/ e backend/
  • Variáveis de ambiente (.env) para secrets e URLs
  • Scripts: dev, build, prisma migrate, seed
  • Deploy previsto: API Node + PostgreSQL + frontend estático (Vite build)
TS · React · Vite TS · Fastify · Prisma PostgreSQL MSAL · JWT · Rate-limit WhatsApp API · Socket.io IA de leitura de imagem Zod · Nodemailer
03 · Acesso

Login, permissões e menu lateral

Entrada corporativa (Microsoft) e menu montado dinamicamente conforme as telas liberadas de cada usuário.

Principal

Tela de login

Logo RC + botão “Entrar com Microsoft”. Em produção: SSO via Entra ID (MSAL). No protótipo, entra direto (sem senha).

Principal

Visão do atendente (Carlos)

Menu reduzido — só Conversas. Ideal para demonstrar permissão mínima.

Principal

Visão do administrador (Paulo)

Menu completo: Atendimento, Ocorrências, Chamados, Gestão e Administração.

Novo

Menu lateral recolhível

O botão ☰ dentro do menu reduz a barra lateral para só os ícones (o nome da tela aparece ao passar o mouse), liberando espaço para o conteúdo. A preferência fica salva no navegador.

Por que permissões por tela e não 5 perfis fixos? O briefing lista os perfis, mas não define quais telas cada um enxerga. Com as telas liberadas por usuário (e um atalho “Administrador” que libera tudo), a RC monta qualquer combinação sem depender de uma alteração no sistema — por exemplo, um atendente que também abre chamados, ou uma liderança que só vê Dashboard e Relatórios. Se preferirem, os 5 perfis podem virar “modelos” que já marcam as telas de cada função.

06 · Notas de coleta

DANFE por foto, sem digitação

Hoje a nota chega por foto no WhatsApp e a chave de acesso é digitada à mão. No sistema, quando o motorista, agregado ou ajudante escolhe “Enviar DANFE” no chatbot, a foto é lida automaticamente: empresa emitente, CNPJ, número/série da NF e chave de acesso.

Novo

Notas de coleta

Indicadores (recebidas, validadas automaticamente, para revisar, confirmadas manualmente), fluxo em 4 passos, busca por chave/CNPJ/NF/empresa e botão para copiar a chave.

Novo

Nota validada automaticamente

Foto ao lado dos dados lidos e a conversa do chatbot. A chave é conferida sozinha: 44 dígitos, dígito verificador, modelo 55, e o CNPJ e o número que estão dentro da chave batem com os lidos da nota.

Secundária

Para revisar — dígito lido errado

Se algo não bate, a nota vai para “Revisar” com os campos em vermelho. Basta corrigir olhando a foto — não é preciso digitar a chave inteira.

Secundária

Para revisar — foto cortada

Chave incompleta: o botão “Pedir nova foto” responde o motorista pelo WhatsApp.

Como a leitura funciona: o código de barras da DANFE é a própria chave de acesso, então o sistema lê o código de barras primeiro (mais preciso) e usa a IA para o texto impresso quando o código estiver amassado ou cortado. Fotos escuras, dobradas ou com várias páginas caem em “Revisar”. Evolução (fora do MVP): com a chave validada, buscar o XML completo da nota na SEFAZ (itens, peso, valor) — exige o certificado digital da RC.

Chamados (Matriz e Filial) + Painel de TV

Abrir chamado para a expedição da Matriz ou da Filial, acompanhar o andamento, complementar informações e exibir na TV do setor com alerta visual/sonoro.

Atualizado

Abrir chamado + Meus chamados

Escolha obrigatória da expedição de destino (Matriz ou Filial), cliente, tipo de veículo, peso (kg/t), horário de corte e e-mail original opcional. Ao lado, a lista dos chamados que a pessoa abriu, com o mesmo status de quem está atendendo.

Dados só leitura — quem abriu não altera o chamado. Para passar uma informação nova, adiciona um complemento (como um acompanhamento no GLPI), que vai direto para quem está trabalhando no chamado.

Novo

Aviso de novo complemento

Na fila da expedição, o chamado ganha o badge “Novo complemento” até ser aberto.

Novo

Novo

Novo

Para a proposta comercial

Este material mostra o MVP visual completo e a stack tecnológica alinhada ao repositório. Serve para a RC validar telas, fluxos, regras de acesso e tecnologias antes (ou durante) o desenvolvimento com backend real.

  • Incluído neste protótipo: todas as telas listadas, navegação por permissão, dados mockados, pendências, notas de coleta por foto, correção de KM, chamados por Matriz/Filial com complementos, cadastro de clientes com chatbot, falhas de integração e auditoria.
  • Stack de produção (já no projeto): React/Vite/TS · Fastify/Prisma/PostgreSQL · MSAL/JWT · WhatsApp API · Socket.io · Zod · rate-limit · Nodemailer · IA de leitura de imagem.
  • Como usar este arquivo: abra no navegador → botão “Imprimir / Salvar PDF” → anexe à proposta ou apresente em reunião.

Pontos para validar com a RC

  • Chatbots por cliente: quais fluxos existem de verdade (no protótipo: menu padrão, cliente com contrato e Policom exclusivo).
  • Envio da DANFE no número de notas/manifesto/odômetro: menu simples (“1 · DANFE, 2 · Odômetro, 3 · Manifesto”) ou identificação automática pela foto.
  • Filial: é uma só ou há mais de uma? Qual o nome (ex.: Jundiaí)?
  • Painel de TV por unidade: uma TV na doca da Matriz e outra na Filial, cada uma mostrando só a sua unidade?
  • E-mail do cliente no cadastro: incluir para o chamado de expedição puxar o e-mail de confirmação automaticamente?
  • Observações internas da expedição: quem abriu o chamado deve vê-las também, ou só os próprios complementos (como está hoje)?
  • Perfis: manter permissões por tela ou criar “modelos” com os 5 perfis do briefing.
