01 · Visão geral

O que o sistema cobre

Um único ambiente para atendimento via WhatsApp, ocorrências operacionais, check-in de KM, chamados de expedição (com painel de TV), indicadores gerenciais e cadastro de usuários — com permissões por tela (não por “perfil fixo”).

Atendimento Inbox estilo WhatsApp, SLA, transferência, encerramento com motivo/resultado, observação interna.
Ocorrências & KM Protocolos com prioridade/prazo, abertura manual, histórico de km com fotos mockadas.
Expedição Abrir e trabalhar chamado + Painel TV full-screen (destaque âmbar para chamado novo < 3 min).
Gestão & Admin Dashboard (~13 KPIs + gráficos), 9 relatórios, config. de setor, usuários e motoristas.
Importante: as telas abaixo são o protótipo visual (dados fictícios) para fechar escopo e preço. A seção seguinte descreve as linguagens e tecnologias que serão usadas na implementação real.
02 · Stack técnico

Linguagens e tecnologias do projeto

Stack já definida no repositório (frontend + backend). TypeScript de ponta a ponta — mesma linguagem no browser e no servidor, com tipagem forte e menos atrito entre as equipes.

Frontend Interface web

  • TypeScript — linguagem principal
  • React 18 — componentes e telas
  • Vite — build e servidor de desenvolvimento
  • React Router — rotas e proteção de telas
  • CSS Modules — estilos por tela (identidade RC)
  • Recharts — gráficos do Dashboard
  • Socket.io Client — atualização em tempo real

Backend API e serviços

  • TypeScript (Node.js) — linguagem do servidor
  • Fastify — API HTTP de alta performance
  • Prisma — ORM e migrations
  • Zod — validação de payloads
  • Socket.io — push (conversas, painel TV, chamados)
  • Nodemailer — envio de e-mails (confirmação de chamado)
  • tsx — execução em desenvolvimento

Banco Persistência

  • PostgreSQL — banco relacional principal
  • Prisma Migrate — versionamento do schema
  • Entidades: usuários, setores, atendimentos, mensagens, ocorrências, KM, chamados, números WhatsApp
  • Índices e enums tipados no schema (status, papéis, direção da mensagem…)

Segurança Auth e proteção

  • Microsoft Entra ID (Azure AD) via MSAL — login corporativo
  • JWT (access + refresh) — sessão da API
  • Cookies HTTP-only — refresh token
  • Rate limit (@fastify/rate-limit) — proteção contra abuso
  • CORS configurado + validação Zod em rotas
  • Permissões por tela — menu e rotas liberadas por usuário (não perfil genérico)
  • Socket autenticado com JWT no handshake

Integrações WhatsApp e tempo real

  • WhatsApp Business API — webhook de entrada + envio de mensagens
  • Números separados (clientes / motoristas) no cadastro
  • Socket.io — fila ao vivo por setor e painel de TV
  • E-mail de confirmação nos chamados de expedição

Ops Ambiente e entrega

  • Monorepo: pastas frontend/ e backend/
  • Variáveis de ambiente (.env) para secrets e URLs
  • Scripts: dev, build, prisma migrate, seed
  • Deploy previsto: API Node + PostgreSQL + frontend estático (Vite build)
TS · React · Vite TS · Fastify · Prisma PostgreSQL MSAL · JWT · Rate-limit WhatsApp API · Socket.io Zod · Nodemailer
03 · Acesso

Login e permissões

Entrada corporativa (Microsoft) e menu montado dinamicamente conforme as telas liberadas de cada usuário.

Principal

Tela de login

Logo RC + botão “Entrar com Microsoft”. Em produção: SSO via Entra ID (MSAL). No protótipo, entra direto (sem senha).

Principal

Visão do atendente (Carlos)

Sidebar reduzida — só Conversas. Ideal para demonstrar permissão mínima.

Principal

Visão do administrador (Paulo)

Menu completo: Atendimento, Ocorrências, Chamados, Gestão e Administração.

04 · Atendimento

Conversas WhatsApp

Lista + chat em duas colunas, filtros Todas/Minhas/Setor, badges de tipo e SLA, transferência e encerramento.

Principal

Inbox de conversas

Contatos Motorista / Agregado / Cliente / Lead; SLA crítico em vermelho; observação interna com cadeado.

Secundária

Modal Encerrar atendimento

Motivo (optgroups), resultado do atendimento e descrição complementar.

Secundária

Busca avançada

Campos: nome, telefone, protocolo, NF, CT-e, placa, pedido, motivo, resultado, responsável, período.

05 · Operacional

Ocorrências e Check-in de KM

Independente da conversa do WhatsApp. Protocolos com prioridade e prazo; KM é histórico/relatório (não a interação do motorista).

Principal

Lista de ocorrências

Filtros por status, prioridade, responsável e período. Botão “Nova ocorrência” para abertura manual.

Secundária

Modal Nova ocorrência

Cliente/motorista, motivo, prioridade, prazo e responsável — gera protocolo e entra como Aberta.

Principal

Check-in de KM

Histórico com km inicial/final, km rodado e status ok / pendente de fechamento (registros via WhatsApp).

06 · Expedição

Chamados + Painel de TV

Abrir chamado por formulário estruturado (sem IA), trabalhar na fila e exibir na TV do setor com alerta visual/sonoro.

Principal

Abrir chamado

Formulário: cliente, tipo de veículo, peso (kg/t), horário de corte (atalhos) e e-mail original opcional — sem análise automática.

Principal

Trabalhar chamado

Fila (abertos / em andamento / e-mail pendente), detalhe, observação e marcar como resolvido.

Secundária

Painel TV — splash

Toque para liberar áudio de alerta (requisito de browser).

Principal

Painel da expedição

Full-screen: card âmbar para chamado novo (< 3 min), branco (aberto) e azul (em andamento).

07 · Gestão

Dashboard e Relatórios

Visível para quem tiver as telas liberadas (ex.: liderança / administrador).

Principal

Dashboard — indicadores

~13 KPIs (atendimentos, SLA, ocorrências, leads, km, reaberturas, clientes ativos…) + filtros.

Principal

Dashboard — gráficos

Volume, motivos, SLA por setor, tipos de contato, prioridades, tops, reclamações, produtividade, comparativo.

Principal

Relatórios

9 cards com exportação visual Excel / PDF (Volume, Motivos, Reclamações, Ocorrências, Históricos, Produtividade, Reincidência, Comparativo).

08 · Administração

Setor, usuários e motoristas

Configuração de SLA/limites e cadastro com checkboxes de telas liberadas.

Principal

Configurações de setor

SLA em minutos + limite de atendimentos simultâneos por agente. Aviso Jundiaí → Matriz.

Principal

Usuários do sistema

Nome, e-mail, setor, badges de telas liberadas e status. Administrador vê tudo.

Secundária

Modal Novo usuário

Toggle Administrador + checkboxes de telas liberadas.

Principal

Motoristas e Agregados

Nome, telefone, tipo, placa e status — cadastro separado dos usuários do escritório.
